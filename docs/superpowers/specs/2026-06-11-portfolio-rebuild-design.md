# ポートフォリオサイト作り直し 設計仕様書

- **日付**: 2026-06-11
- **対象**: `yui666a.me`（相曽 結 / AISO Hitoshi の個人ポートフォリオ）
- **背景**: 5年前に作った素のHTML/CSS/JS製サイト（UA判定でPC/SP出し分け、AR名刺、スキルロゴ一覧）を、Astroで1から作り直す。

---

## 1. 目的

| 区分 | 目的 |
|---|---|
| **メイン** | 信頼感ある「名刺」。経歴・スキル・実績を整理し、採用担当・EMに「ちゃんとした人」と伝える |
| **サブ** | 技術力と自分らしさを示す「遊び場」。3D/WebGL表現でエンジニアとしての尖りを見せる |

この2つはページ単位で役割分担し、両立させる（堅実な入口 ＋ 尖った見せ場）。

## 2. ターゲット読み手

- **主**: 日本の採用担当・エンジニアリングマネージャー（日本語ベース）
- **副**: 海外含む技術者コミュニティ（英語でも読める）
- → **JP/EN 完全対応**を最初から構造に組み込む。

## 3. 成果物（Works）の前提

- 公開できる成果物が複数ある（GitHubリポジトリ、Webサービス/アプリ、AR名刺など）。
- 「並べてリンクし、各々に短い語りを添える」作りが活きる。
- データ駆動で管理し、増えたらファイルを足すだけにする。

---

## 4. サイト構成

```
ポートフォリオサイト (Astro / static / GitHub Pages, yui666a.me)
│
├── トップ (1ページ縦スクロール) … 名刺の本体
│     /        … 日本語 (デフォルト)
│     /en/     … 英語
│     構成: Hero → About → Skills → Works → Links
│
├── Playground (見せ場・別ページ) … 技術力と遊び
│     /playground/, /en/playground/
│     Three.js を Astro Island (client:visible) で隔離
│
└── (任意・将来) Works詳細 /works/[slug]/ … ケーススタディ
```

- トップは**1ページ縦スクロール**。採用担当がスクロールするだけで全体像を掴める。
- 見せ場（3D/WebGL）は**別ページ**に切り出し、トップからは入口として誘導。
- 自前ブログは持たない（発信は Qiita/Zenn リンクで代替）。

## 5. レイアウト & トーン

- **レイアウト**: 1カラム中央寄せ（王道・読み手に優しい・スマホと相性良い）。
- **トーン**: ミニマル・洗練（信頼寄り）。余白とタイポで「静かな信頼感」。遊びは Playground に隔離。
- **配色**: モノトーン（白〜オフホワイト背景／濃いグレー〜黒文字）＋ **差し色1色**（差し色は未確定 → 後で決定）。
- **タイポグラフィ**: 日本語＝可読性の高いゴシック、英数字＝上質なサンセリフ。装飾フォントは使わない。
- **動き**: トップは控えめ（スクロールでふわっと現れる程度）。派手なアニメは Playground に隔離。
- **レスポンシブ**: CSS のレスポンシブ1本に統一。**旧サイトの UA 判定によるページ出し分けは廃止**（保守簡素化）。

## 6. トップ各セクションの内容

| セクション | 内容 |
|---|---|
| **Hero** | 名前＋肩書＋一言。右上に言語切替(JP/EN)＋簡易ナビ。Playgroundへの入口ボタン。装飾は最小限 |
| **About / 経歴** | 短いプロフィール文、学歴・職歴のタイムライン（奈良高専→長岡技科大→現職…）、顔写真は任意 |
| **Skills** | カテゴリ別（言語/フレームワーク/インフラ・ツール等）にロゴ＋名称。習熟度の強弱表示は未確定 |
| **Works（主役）** | 成果物カードのグリッド（タイトル・サムネ・1行説明・技術タグ・リンク）。外部リンク直行、将来 /works/[slug] に拡張可。AR名刺もカードとして配置 |
| **Links** | GitHub・Qiita・Zenn・X(SNS)・Mail をアイコン＋ラベルで集約。発信ハブとして締める |

## 7. Playground（見せ場）

- Three.js による 3D 表現を1ページに隔離。`client:visible` で画面到達時に初めて読み込み、トップの速度に影響させない。
- 段階的に作る：まず「動く3Dが置ける器」を用意。表示する中身（AR名刺の3Dモデル流用 / 新作 / インタラクティブ）は後で詰める（YAGNI）。
- 旧サイトの AR 資産（`ar/obj/*.glb`, `*.vrm` 等）は流用候補として温存。

---

## 8. 技術方針

- **スタック**: Astro（static出力）。
  - 理由: ほぼ静的＋一部だけ動的という性質に最適。デフォルトJSゼロで軽量・高速。必要箇所だけ Islands で JS を載せられる。
  - 標準の i18n ルーティング（`/` ⇄ `/en/`）が JP/EN 完全対応と相性良い。
- **3D**: Three.js を Astro Island として Playground にのみ読み込む。
- **i18n**: Astro 標準 i18n。文言を `src/i18n/ja.json` / `en.json` に集約し、全セクションが参照。
- **コンポーネント分割**: 各セクションを独立した `.astro` コンポーネントに（1ファイル1責務）。
- **データ駆動**: Works・Skills は Markdown/JSON データで管理。本文とロジックを分離。
- **配信**: GitHub Pages 継続（`yui666a.me` ドメイン維持）。
  - 注意点: GitHub Pages 環境での i18n ルーティングと独自ドメイン（CNAME）維持を実装時に織り込む。

## 9. 移行・既存資産

- 既存リポジトリ（素のHTML/CSS/JS）は Astro プロジェクトへ置き換え。
- 流用候補: 顔写真（`img/aiso*.jpeg`）、スキルロゴ（`img/logo/*`）、AR/3D資産（`ar/obj/*`）。
- 廃止: `ua_redirector.js` による出し分け、`pc.html`/`sp.html` 二重管理。
- `CNAME`（yui666a.me）は維持。
